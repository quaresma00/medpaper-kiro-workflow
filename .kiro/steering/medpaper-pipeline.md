# medpaper ENGINE workspace (mother workflow) - maintenance only

> **If you are a delegated subagent, stop here.** Steering is shared with subagents and is not
> isolated, so this file reaches you even when it should not. If you were invoked to review,
> audit, read a full text or gather context, none of it applies to you: do not run `wf`
> commands, do not advance a stage, do not write pipeline artifacts. Do the job you were given
> and report back. Your own agent prompt governs; this file does not.

This workspace is the medpaper ENGINE: the shared, pure workflow that drives every paper. It is
maintenance only. No paper may live in it, be selected in it, or write into it.

- Never create, select or continue a paper here. Start one with
  `python tools/wf.py new <slug>` and open the folder it prints as its own Kiro workspace.
- `python tools/wf.py status` here prints the ENGINE WORKSPACE banner (papers root, papers,
  selection); paper-driving commands are refused from this folder.
- The pipeline has 25 stages, defined in `pipeline/pipeline.toml` with one card per stage in
  `pipeline/stages/`. Edits to `pipeline/`, `tools/`, `reference/` or `.kiro/` change every
  paper, so keep them general.
- Every engine edit must keep `.\.venv\Scripts\python.exe -B tools\selftest.py` all-pass and
  `python tools/install_adapters.py --check` in sync; `python tools/wf.py doctor` must stay OK.
- `.kiro/steering/` and `.kiro/hooks/` are generated by `tools/install_adapters.py` from
  `tools/wfcore/adapters.py`; never hand-edit them.
- Python/R division of labour: `reference/language_policy.toml` (figures default to R).
